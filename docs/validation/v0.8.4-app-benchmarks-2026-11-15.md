## Scope and cache proof

- Full configured native-DOM/unit/component suites, eight workers, serial observations. No Chromium performance claim.
- Payroll: 26,360 passed / 2,051 files every observation, same committed app fix `49da952428cff8c9aec3bf46b56d3f317378e009` in both arms. UI: 7,408 passed / 464 files. Chat: 785 passed / 68 files. Zero failures or load errors.
- Website: same 1,652 case identities / 114 files ; 0.8.3 executes 1,645 and skips 7, candidate executes 1,647 and skips 5. The two HMAC skip-to-pass cases are named in JSON. No tests were excluded.
- Cold: fresh process, fresh TMPDIR, empty private tool/bundle cache each observation. OS disk caches were not purged.
- Warm: each version primed its own private tool cache once, then fresh process/TMPDIR per timed observation. Primes are excluded from medians.
- Payroll warm native cache hits: 83% in both arms, persistent file counts unchanged across timed arms (12,528 baseline / 12,530 candidate). UI/chat/website timed warm native hits: 100%.

## Background and interpretation limits

- Measurements are non-isolated. Cold inventories filtered developer processes and could omit direct surf/DOM test binaries as well as VM/GUI processes; full prestart quiescence snapshots exist. That missing history is not fabricated. All cold observations are retained; no selective reruns or discarded outliers.
- Warm observations record full process inventories before/after every arm. A foreign surf isolation test consumed roughly one core during early payroll arms and was replaced by a render test before disappearing; the arms experienced different foreign-job lifetimes. Potential contamination is explicit in JSON. Boundary inventories are not continuous CPU profiles.
- UI warm measured +1.97% wall / +2.02% CPU; it is not rounded into a nominal zero. The observed variation does not establish a statistically significant or causal regression.
- Binary hashes/source commits are exact. Compiler versions were not recorded in the official/candidate receipts; no same-toolchain claim. Candidate receipt records a successful optimized release build.
